## 3. 论文整体组成和顺序

按原模板展示顺序组织：

1. 封面。
2. 诚信承诺书。
3. 目录。
4. 中文摘要及关键词。
5. 英文摘要及关键词。
6. 正文，包括绪论、研究展开及结论等。
7. 致谢。
8. 参考文献。
9. 附录，按实际写作内容设置。

模板目录及实际摘要页均用罗马数字 `Ⅰ`、`Ⅱ` 表示中英文摘要页码，正文及后续部分示例采用阿拉伯数字。页码居中要求及编号适用范围见第4.6节；封面、承诺书和目录是否计页、是否显示页码，以及分节方式，原文没有完整说明，定稿前需确认。

原文在附录处写有“附录1（根据实际写作内容确定是否包含目录）”，措辞存在歧义，不能据此认定附录必须有、必须无或必须不进入目录。实际是否设置附录及其目录收录方式需确认。

## 4. Word 排版规范

| --- | --- |
| “目录”标题 | 三号黑体，居中，标题后空一行 |
| 摘要、Abstract及正文一级标题条目 | 小四号黑体，左对齐 |
| 二级标题条目 | 小四号宋体，缩进 |

项目执行建议：英文摘要与中文摘要在研究目标、方法、结果及关键词上保持一致，不能在翻译时添加未验证的结论。原文没有单独规定英文摘要字数。

### 4.4 正文标题与段落

| 层级或内容 | 原文标注 | 编号示例 |
| --- | --- | --- |
| 一级标题 | 三号黑体，居中 | `2 住房市场分析` |
| 二级标题 | 小三号黑体 | `2.1 住房市场概述` |
| 三级标题 | 四号黑体 | `2.1.1 住房概念` |
| 正文段落 | 小四号宋体，首行缩进两字，1.5倍行距 | 普通段落 |
| 文内引用 | 方括号数字上标 | `[1]` |

正文各部分均按同一规则排版。示例用 `①`、`②` 列举段内要点，但未规定所有列表必须采用该符号。

原文只明确一级标题居中，未明示二、三级标题的对齐方式、标题编号后空格宽度及段前段后间距，不应把示例中的随意空格当成精确要求。

### 4.5 参考文献排版

- “参考文献”标题：三号黑体、居中，标题后空一行。
- 每条参考文献顶左书写。
- 中文参考文献：小四号宋体。
- 英文参考文献：小四号 Times New Roman。
- 行距：1.5倍。

字体字号换算仅供设置工具时使用：二号22 pt、三号16 pt、小三号15 pt、四号14 pt、小四号12 pt。这是常用字号换算，不是原文额外提出的规则。

## 5. 选题和题目

选题应结合实际工作的企业、项目，或具有丰富可靠数据来源的对象，落在专业的某个细分领域或微观研究方向。研究范围要能支撑有深度的分析和有意义的结论。

计算机科学与技术专业的原文题目范式为：**基于XX技术的XX项目的设计与实现**。这是选题示例，不要求机械套用，也不意味着本项目论文题目已确定。

题目需准确、具体、简明，明确研究对象和核心内容，并与实际完成的工作一致。避免：

- 信息含糊、意义空泛，无法识别具体研究内容。
- 核心内容提炼不足，变量或概念之间逻辑不通。
- 专有名词、修饰词使用不准确。
- 题目和正文不一致，范围、深度或覆盖面不匹配。
- 题目过大、言过其实、以偏概全。
- 结构复杂、修饰过多、冗长重复。

## 6. 各部分内容写作要求

### 6.1 摘要与关键词

摘要按以下信息顺序组织，句数为原文给出的写作指导：

| 信息 | 建议篇幅 | 应回答的问题 |
| --- | --- | --- |
| 背景或目的 | 1—2句 | 为什么研究，核心问题是什么 |
| 方法 | 1—2句 | 采用什么设计、方法、数据来源或理论框架，如何开展研究 |
| 主要结果 | 2—3句 | 得到了什么关键发现或核心结论，应有具体数据或结论性表述 |
| 意义或价值 | 1句 | 解决或改进了什么问题，有什么学术或实践贡献 |

摘要通常300—500字，应独立完整，使读者仅阅读摘要即可理解研究意义、方法、过程和结果。采用“本研究”“结果表明”等第三人称表达；不引用文献，不使用图表或公式，不作主观评价。

关键词一般3—5个，从论文中选择能代表主要内容、关键技术或核心概念的单词或术语。

### 6.2 绪论

绪论至少交代以下内容：

- 研究背景：相关领域的现状。
- 研究意义：研究的学术或实践价值。
- 研究目标：论文要解决的核心问题。

项目执行建议：将道路运输培训中的具体问题与系统研究目标对应起来，后续设计、实现和测试应能回应这些目标。

### 6.3 文献综述

列举6—8个相关领域的中外研究进展，最好选取近五年的成果。介绍每项研究时说明时间、作者、研究内容、研究方法或技术、结果，以及存在的不足。

综述最后应分析已有研究的不足，引出本研究的创新点或自己的观点。不能把资料简单罗列、堆叠而没有比较、评价和总结。

文献选择应紧扣题目，优先具有代表性的权威文献，同时兼顾新文献。避免为凑数量加入大量低相关资料；避免未读全文就二次转引、曲解原意，或在未理解外文原文时错误翻译。

综述中的6—8个研究进展不等于整篇论文只需6—8条参考文献；全文文献数量要求另见第8节。

### 6.4 理论分析

介绍研究涉及的理论及其原理，为后续研究和观点提供依据。选取最相关的理论，说明如何用它分析本论文的问题，突出与本研究有关的特征和作用。

避免拼凑理论、无关铺陈，或只提出某种理论、系统名称而不说明用途。

项目执行建议：技术介绍应服务于后续方案选择和实现分析，不要将这一部分写成框架名称或官方简介的集合。

### 6.5 研究过程与数据分析

这一部分应体现工作量，交代研究流程、数据收集、分析方法和结果。复杂信息可使用流程图、对比表格等可视化方式呈现。

**研究设计**：以理论或模型为依据，保证科学性；原文建议采用对比法、设置对照，体现研究带来的优势或提升，并提高数据对论文观点的说服力。

**数据收集**：必要时详细描述收集过程。数据需可靠、相关、有代表性，能支持后续分析和结论；同时考虑充分性和时效性，能反映研究时期的水平和研究深度。

**数据分析**：基于科学理论或模型，采用合理方法，开展定量或定性分析，如实描述结果。可进行横向比较或纵向比较，并进一步解释造成现象或结果的原因。

避免以下问题：

- 缺少关键论证要素，研究过程不完整。
- 章节逻辑脱节，前面发现的问题在后面的方案和实施中没有解决。
- 只罗列现象，没有归类和追溯原因。
- 方案选择缺少多方案比较，实施缺少详细计划。

### 6.6 对策或解决方案

针对分析得到的原因逐一提出解决方案，并论证科学性和可行性。解决措施必须回应前面发现的问题，论证方法和证据应具有说服力。

项目执行建议：软件论文可通过需求分析、系统设计、核心实现和测试验证承接这一内容，不必机械使用“对策研究”作为章节标题。

### 6.7 总结与展望

概括研究内容、分析过程、主要发现和自己的创新想法，说明不足，提出未来研究方向及实际应用建议。

结论应回应研究问题，体现文章价值和实际作用，不能只是重复各章内容、摘要或引言。结论的强度应与证据一致；无法完全肯定的内容应保留适当限定，避免“国际国内领先水平”“有很高的学术价值”等自我评价或口号。

原文在结论注意事项中还举出宏观政策与微观政策结合、提出针对性政策建议的表述；应按研究主题理解其适用性，不必据此为软件项目强加政策研究内容。

### 6.8 致谢

表达应真诚而具体，感谢实际在研究、项目、论文写作及相关学术或非学术工作中给予帮助和支持的人。

## 7. 本项目的章节与证据组织建议

本节属于项目执行建议，不是学校强制章节模板。可根据指导教师意见调整章节名称与合并方式，但应覆盖第6节的内容要求。

| 可采用的章节 | 应组织的内容与证据 |
| --- | --- |
| 绪论 | 业务背景、具体问题、研究意义和目标；文献综述可放本章或单独成章 |
| 相关理论与技术 | 与系统方案有关的理论、关键技术及选择依据 |
| 需求与可行性分析 | 用户角色、业务流程、功能和非功能需求、范围及约束 |
| 系统设计 | 总体架构、模块职责、数据库、核心流程和方案比较 |
| 系统实现 | 实际完成的功能、关键机制、代码依据和界面证据 |
| 测试与结果分析 | 测试环境、数据来源、用例、实际结果、问题原因及改进验证 |
| 总结与展望 | 已完成目标、实际贡献、局限和未完成事项 |

保持“问题—目标—方案—实现—验证—结论”的对应关系。对性能提升、识别效果、稳定性等描述，应有可追溯的测试或研究证据；未测量的指标不填写推测数值，未实现的功能不写成既有成果。

## 8. 参考文献与引用规范

### 8.1 选材与数量

- 文献必须与研究主题直接相关，至少覆盖文献综述涉及的研究。
- 优先核心期刊论文、学术专著、学位论文、国际会议论文等高质量资料。
- 原文对学位论文表述为：**建议20篇以上，其中国外文献需3篇以上**。总量是建议性措辞，国外文献部分使用“需”，不可一并弱化为可选。
- 理工科建议近5年文献占比≥50%；人文社科可适当放宽，但应包含经典理论文献。
- “近5年”应随实际写作时间核算，不固定成某一组年份。
- 避免文献数量不足、来源单一、范围过窄、过于陈旧、质量不佳。

### 8.2 编号与正文对应

模板格式页明确要求前言和正文引用采用方括号数字上标，因此本项目按顺序编码方式统一组织，正文中首次出现的文献依次编号，同一文献重复引用沿用同一编号。

原文后面的通用注意事项提到“顺序编码制或著者—出版年制”，但没有撤销前面具体的数字上标要求；本项目不混用作者年份标注。

文后每一条资料都应有对应正文引用，正文每一个编号都应有对应文后条目。标点、作者名缩写和斜体等处理应全文统一，避免缺项、类型代码错误或编号紊乱。

Markdown 中的 `[1]` 仅作编号示意，正式 Word 稿需设置为真正的上标。

### 8.3 著录格式

原文说明参考文献格式主要参考《文后参考文献著录规则》（GB/T 7714-2015）制定；专利、报告、标准、报纸等其他类型参照该标准执行。以下根据原文说明和示例整理字段，未另行扩展为该标准的完整解释。

原文说明行以括号描述“文献类别代码”，实际示例使用 `[J]` 等方括号标识；下面按实际示例书写。原文个别示例的标点并不完全一致，正式稿需统一。

```text
期刊
[序号] 作者. 文献题名[J]. 刊名, 出版年份, 卷号(期号): 起止页码.

著作 教材
[序号] 作者. 文献题名[M]. 出版地: 出版者, 出版年.

会议录 论文集
[序号] 作者. 文献题名[C]. 出版地: 出版者, 出版年, 起止页码.

学位论文
[序号] 作者. 文献题名[D]. 保存地: 保存单位, 年份.

电子文献 按出版年著录
[序号] 作者. 电子文献题名[文献类别代码/载体类型代码]. [出版地: 出版者], 出版年[引用日期]. 获取和访问路径.

电子文献 按更新或修改日期著录
[序号] 作者. 电子文献题名[文献类别代码/载体类型代码]. (更新或修改日期)[引用日期]. 获取和访问路径.
```

电子文献按实际来源选择日期写法。使用更新或修改日期时，日期外保留圆括号，引用日期用方括号，例如原文的 `(2001-12-19)[2002-04-15]`。

期刊、著作教材、会议录论文集、电子文献的作者按原文只列前三名；超过三名时，示例以“等”或“et al.”表示其余作者。期刊有期号时填写期号。电子文献的出版信息、更新日期等应按实际来源及适用标准填写，不能为了补齐格式而编造。

## 10. 定稿检查清单

### 内容与证据

- [ ] 题目具体准确，与实际完成的研究范围一致。
- [ ] 正文满足8000字以上要求，并留有适当余量。
- [ ] 摘要覆盖背景或目的、方法、结果及价值，通常300—500字。
- [ ] 摘要使用第三人称，没有引文、图表、公式或夸大评价。
- [ ] 关键词一般3—5个，中英文内容对应。
- [ ] 绪论交代背景、意义和核心研究目标。
